# 方法论：什么让一个结论算数

> 这份文档承载**判断标准**，不承载代码。
>
> 代码会过时、框架会换，但这份文档里的判据不会。
> 任何实验，违反本文任意一条，结论作废——不进 journal，不用于决策。

---

## 一、四条判据

流程是否正当，只看这四条。任意缺一条，回测数字就不可信；四条齐备，**年化 1% 就是真的 1%**，可以复利、可以叠加。

| # | 判据 | 不合格 | 合格 |
|---|---|---|---|
| 1 | **样本外只碰一次** | 反复在测试集上调参 | 预注册区间，样本外只跑一次 |
| 2 | **多重检验惩罚** | 试了 50 个想法，最好的那个直接信 | 按试错次数折价后再判断 |
| 3 | **可交易性** | 涨停照买、跌停照卖、零成本 | 涨跌停过滤 + 真实成本 + 停牌处理 |
| 4 | **PIT（时点正确）** | 用报告期财报、用今天的指数成分 | 用公告日、用历史成分、用当时的股票池 |

### 判据 1：预注册

跑之前，把下面五项写死在文件里：

```
训练区间：
验证区间：
样本外区间：
评估指标：
通过阈值：
```

跑完只允许两种结论：**达标 / 不达标**。

不允许：看完结果再调阈值、再截区间、再换指标。这类操作有个名字叫 HARKing（Hypothesizing After Results are Known），它不会报错，只会让你永远在原地打转。

**样本外一旦被看过，那个区间就作废了。** 没有第二次机会，这是它唯一有价值的原因。

### 判据 2：多重检验惩罚

你试了 N 个想法，挑出最好的那个，它的显著性必须按 N 折价。

三个工具，按顺序用：

| 工具 | 回答什么问题 | 判据 |
|---|---|---|
| **Purged CV** | 我的交叉验证本身有没有泄漏？ | 见下节 |
| **PBO**（回测过拟合概率） | 我的最优参数在样本外会不会崩？ | PBO < 0.3 可用，0.5 等于抛硬币 |
| **DSR**（Deflated Sharpe） | 这个 Sharpe 扣掉"试了很多次"之后还显著吗？ | DSR > 0 才算通过 |

经验参考（Harvey, Liu & Zhu）：考虑了多重检验后，**t 统计量要 > 3** 才值得认真对待，而不是传统的 2。

### 判据 3：可交易性

A 股这条最狠，绝大多数"年化 30%"死在这里。

至少要处理：

- **涨停不能买、跌停不能卖**（注意方向，v0.6 的 qlib 曾把这里写反）
- **停牌剔除**，停牌期间不调仓、不计算收益
- **ST 涨跌停是 5%**，创业板/科创板是 20%，阈值要按板块分层，不能全局 9.5%
- **成本**：印花税（卖出）、佣金、滑点、冲击成本。50 只票日换手 10% 的策略，成本能吃掉三分之一收益

### 判据 4：PIT（Point-in-Time）

只用"当时真的能看到"的信息。

| 场景 | 错误做法 | 正确做法 |
|---|---|---|
| 财务数据 | 报告期 `statDate` | 公告日 `pub_date` |
| 指数成分 | 今天的沪深300 | `get_index_stocks(index, date=...)` |
| 股票池 | 现存股票 | 历史存续，含已退市 |
| 复权 | 前复权价格 | 原始价 + 复权因子 |

**PIT 违规最危险的地方是不报错。** 它只会让你的回测悄悄变好看。

## 二、Purged Cross-Validation：为什么普通 K-Fold 一定错

金融数据有两个特性，让普通 K-Fold 必然泄漏：

```
样本 A: ├──── 特征窗口 ────┬── 标签窗口 ──┤
样本 B:              ├──── 特征窗口 ────┬── 标签窗口 ──┤
                     ↑ 重叠区
```

1. **标签有重叠期**：用未来 2 天收益做标签，相邻两天的样本，标签窗口重叠了 1 天
2. **序列强自相关**：相邻样本的特征高度相似

结果：训练集里"已经知道"了验证集的答案。IC 虚高，实盘归零。

**修正方法（López de Prado, AFML 第 7 章）**：

| 手段 | 做法 |
|---|---|
| **Purging** | 删除训练集中，标签窗口与验证集时间重叠的样本 |
| **Embargo** | 在训练集和验证集之间留一段隔离带（通常取标签窗口长度的 1%） |

在 A 股日频、2 日标签的设定下，embargo 取 5 个交易日左右是常见起点。

qlib 默认的 `segments` 硬切是**最粗粒度的 purge**（三段完全不重叠），已经比随机 K-Fold 好得多。但如果你想做多折验证，必须自己实现 purge + embargo，这一步框架不帮你。

## 三、实验记录的格式

每次实验，四行。缺一行就不算实验完成。

```markdown
## YYYY-MM-DD 实验标题

**假设**：一句话，可证伪。
**预注册**：训练 A–B / 验证 C–D / 样本外 E–F；指标 X；阈值 Y。
**结果**：样本外含成本年化 __%，IR __，回撤 __%；PBO __；DSR __。
**裁决**：通过 / 证伪。原因：__。
```

### 为什么是这四行

| 行 | 作用 | 缺失后果 |
|---|---|---|
| 假设 | 防止"先跑再看" | 你会在数据里找到无数个假规律 |
| 预注册 | 防止事后调阈值 | 所有结论都变成"再试一次就对了" |
| 结果 | 可对比、可复现 | 三个月后无法回答"上次怎么来的" |
| 裁决 | 形成判断力 | 你只有经历，没有经验 |

**"证伪"的记录比"通过"值钱十倍。** 通过可能是运气，证伪永久排除了一个方向。

## 四、失败清单

单独维护一份，越厚越好。每条格式：

```
[方向] 一句话描述
[为什么失败] 数据/逻辑/成本/样本外失效
[证据] 指向 journal 里对应的实验编号
[结论] 以后不再尝试，除非条件变为 __
```

失败清单的作用不是让你记住痛苦，是**让你不再重复投入**。

失败清单越厚，你判断"什么方向不值得做"的速度越快。这是判断力的直接来源。

## 五、框架选型：为什么是 Qlib

### 候选对比

| 框架 | 强项 | 弱项 | 适合 |
|---|---|---|---|
| **Qlib** | 全链路 ML 流水线、统一评估口径、实验记录、表达式因子、滚动训练 | 学习曲线陡、数据格式封闭、无防过拟合机制 | **截面选股研究** |
| PyBroker | 轻量、ML 原生、`walkforward()` 一行 | 无统一因子库、无实验记录 | 单标的、快速验证 |
| vectorbt | 向量化极快、参数扫描 | 只做回测，不做研究流水线 | 参数敏感性测试 |
| backtrader / zipline | 事件驱动、生态老 | ML 流程全在框架外 | 传统规则策略 |
| nautilus_trader | 撮合精度高、实盘强 | 无研究流水线 | 实盘执行 |

### 结论

**选 Qlib，因为它提供的是"研究基础设施"，不是"回测器"。**

具体是下面三样东西不可替代：

1. **统一评估口径** —— 20+ 模型跑在同一数据、同一套指标下，实验之间才可比。没有可比性就没有积累。
2. **表达式因子引擎** —— 加因子是加一行公式，不是加一个脚本。这让迭代成本降到最低。
3. **实验记录** —— 每次预测、IC、模型自动落盘。

**它给你的不是模型，是纪律的容器。**

### 它给不了什么

必须清楚，否则会误以为用了 Qlib 就安全了：

| 缺什么 | 后果 | 补法 |
|---|---|---|
| 无 PBO / DSR | 不知道自己试了多少次 | 自己实现，见本文第二节 |
| 无 purged CV | 多折验证会泄漏 | 自己实现 purge + embargo |
| Alpha158 被反复筛选过 | 它的 baseline 本身就是过拟合标本 | 换因子，且必须在未筛选过的区间验证 |
| 无 PIT 财务数据 | 加基本面因子时立刻违规 | 自己接，用公告日 |
| 不支持复杂事件驱动 | 想写"跌破均线止损"很别扭 | 这类需求换框架 |

**定性：低维护、稳定但不再快速演进。** 不是废弃。

### 会不会过时：分三层看

| 层次 | 内容 | 3 年后 |
|---|---|---|
| 数据协议 | `(datetime, instrument)` 二维索引、价格与复权因子分离 | 不过时 |
| 研究协议 | 时间切分、训练期拟合标准化、固定 baseline 对照 | 不过时 |
| 代码实现 | 具体 API、模型封装、mlflow 集成 | **会过时** |

**你从它身上要提取的是前两层。**

### 对冲措施（已实施）

1. **源码 editable 安装** —— 代码在本仓库 `vendor/qlib`，上游归档也能跑
2. **数据本地化** —— 510MB 在自己硬盘，不依赖官方下载
3. **journal / constraints 与框架解耦** —— 换框架只改执行层
4. **关键逻辑自己实现** —— purged CV、PBO 抄进 `constraints/`，不依赖其内部 API
5. **年度体检** —— 换台机器，30 分钟内用 `reproduce_baseline.sh` 跑出 8.07%

**验收标准：能在 30 分钟内复现基准的系统，就不会因为上游停更而死。**

## 七、框架更换条款

防止"为了追新框架而再次归零"。想换框架，先过这道闸门。

### 允许更换的条件（满足任意两条）

1. 当前框架**连续 12 个月无任何提交**，且存在阻塞研究的缺陷
2. 出现**明确更优**的替代方案，且能证明在**同一基准、同一数据**下结果更可信
3. 当前框架的某项必备能力（如 purged CV）无法通过扩展实现

### 更换时必须无损迁移的资产

| 资产 | 迁移要求 |
|---|---|
| `journal/` 全部记录 | 一条不丢，格式不变 |
| 冻结基准的数字与数据指纹 | 必须能在新框架上复现到可解释的程度，否则新基准必须说明差异根因 |
| `constraints/` 全部检查项 | 逐条在新框架上重新落地 |
| 失败清单 | 原样保留 |

### 禁止的更换理由

| 理由 | 为什么禁止 |
|---|---|
| "这个框架 star 更多" | star 衡量传播度，不衡量正确性 |
| "这个框架用了新技术" | 新技术不等于可信结论 |
| "我在这上面做不出结果" | 问题在流程，不在框架。换了还是在原地 |
| "教程更多、学起来更快" | 学得快不代表做得对，可能只是更快地重复错误 |

**判据：如果换框架后，你的 journal 没有变厚，那这次更换就是失败的。**

## 八、待拍板事项

以下需要本人决定，框架和文档都替代不了：

- [ ] **样本外锁定区间**：建议 2022-01 至今（需先接入自有数据，当前官方数据只到 2020-09-25）
- [ ] **可接受的实验轮次上限**：例如每方向 20 次尝试，超过即按 20 次做多重检验校正
- [ ] **PBO / DSR 的通过阈值**：建议 PBO < 0.3，DSR > 0

在样本外区间确定并写入之前，**任何声称"通过样本外验证"的结论都不成立**。

## 九、三条铁律

1. **没有预注册的实验，结果不算数。** 看完结果再定阈值，等于自欺。
2. **样本外只碰一次。** 一旦看过，那个区间就作废了。
3. **失败记录比成功记录值钱。** 成功可能是运气，失败排除了一个方向。
